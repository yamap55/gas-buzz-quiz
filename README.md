# gas-buzz-quiz

Google Apps Script 製の早押し4択クイズアプリ。懇親会などの余興向けに、参加者が各自のスマホから回答する。

## 特徴

GASとGoogleスプレッドシートだけで完結する。サーバーもデータベースも用意する必要がなく、Googleアカウントがあれば追加の費用なしに動かせる。

参加者はURLを開いて名前を入力するだけで参加できる。Googleへのログインは不要。

## 構成

画面は2つある。参加者画面は問題と選択肢を表示して回答を受け付け、管理画面は出題と正解発表を操作する。

データはすべて1つのスプレッドシートに入る。問題・参加者・回答・進行状態と集計用のシートで構成され、当日トラブルが起きても人間が直接開いて確認・修正できる。

# 開発

## 環境

- Google Apps Script（V8ランタイム）
- Google スプレッドシート
- 開発時のみ Node.js と [clasp](https://github.com/google/clasp)

実行時の外部依存はない。npm パッケージも clasp 以外に使っていない。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `src/Code.js` | サーバー側の処理すべて。進行状態の管理、回答の記録、シートの初期化 |
| `src/Index.html` | 参加者画面 |
| `src/Admin.html` | 管理画面 |
| `src/Styles.html` | 両画面で使う配色と土台のスタイル |
| `src/Sync.html` | 両画面で使う時計合わせとポーリング |

`Styles.html` と `Sync.html` は `doGet` がテンプレートとして評価する際に `include_` で取り込まれる。取り込みは `<?!= include_('Sync') ?>` を書いた位置に展開されるため、画面側のスクリプトより前に置く必要がある。

## セットアップ

```bash
npm ci
npx clasp login
```

スプレッドシートとそれに紐づくスクリプトをまとめて作る。

```bash
npx clasp create-script --type sheets --title "早押しクイズ大会" --rootDir ./src
```

コードを反映する。

```bash
npx clasp push
```

スクリプトエディタを開き、`setupSheets` を実行する。必要なシートとサンプル問題が作られる。初回は承認ダイアログが出る。

```bash
npx clasp open-script
```

ウェブアプリとしてデプロイする。

```bash
npx clasp create-deployment --description "初回デプロイ"
```

表示されたデプロイIDから、次の2つのURLが決まる。

- 参加者用: `https://script.google.com/macros/s/<デプロイID>/exec`
- 管理画面: 上記に `?page=admin` を付けたもの

## 開発の流れ

コードの反映先が2つあるので注意する。

`clasp push` はGAS上のコードを更新する。`/dev` で終わるURLに即座に反映されるが、こちらはGoogleログインとスクリプトの編集権限が必要なので、開発中の確認用になる。

```bash
npm run push
```

`/exec` は固定されたバージョンを配信しているため、`push` しただけでは反映されない。同じURLのまま更新するには `update-deployment` を使う。

```bash
npx clasp update-deployment --description "説明" <デプロイID>
```

`create-deployment`（`npm run deploy`）は新しいデプロイを作るのでURLが変わる。当日配布するURLを固定したい場合は使わない。

## 実装上の注意点

理由を知らずに「素直な実装」へ直すと壊れる箇所が2つある。

### getState でスプレッドシートを読まない

参加者画面は数秒ごとに `getState` を呼ぶ。Apps Script の同時実行上限はユーザーあたり30で、スプレッドシートの読み取りは1回1〜2秒かかるため、ここでシートに触ると30人規模で上限に近づく。

進行状態は ScriptProperties に保存し、`getState` はそれだけを読む。スプレッドシートへの書き込みは管理者の操作時と参加者の回答時（1人1問1回）に限定している。

### 問題の表示は絶対時刻で同期する

ポーリングで状態を受け取った瞬間に問題を表示すると、ポーリング間隔ぶんだけ端末ごとに表示タイミングがズレる。これは早押しの順位をそのまま壊す。

サーバーは出題操作の8秒後を絶対時刻 `startAt` として配り、各端末はローカルでカウントダウンして `startAt` ちょうどに表示する。経過時間もクライアントが「押した時刻 - `startAt`」で算出した値を採用する。サーバーの受信時刻は参考値として記録しているだけで、順位には使わない。

端末とサーバーの時計ズレは、ポーリングの往復時間が最小だったサンプルからオフセットを推定して補正している。

# 運用

## 問題の準備

問題シートに1行1問で記入する。

| 列 | 項目 | 内容 |
|---|---|---|
| A | ID | `q01` など。一意にする |
| B | 問題文 | |
| C | 備考 | 正解発表のときに口頭で補足するためのメモ。管理画面にだけ表示され、参加者には渡らない |
| D | 種別 | `text` または `image`。プルダウンから選ぶ |
| E〜H | 選択肢1〜4 | |
| I | 正解 | 1〜4 |
| J | 制限時間(秒) | 空欄なら20秒 |
| K | 最終出題時刻 | 出題時に自動で記録される。記入は不要 |

### 画像問題

種別で `image` を選ぶと、選択肢1〜4に書いたURLを2×2で表示する。

1つの選択肢に複数枚を指定することもできる。`|` で区切って並べると、制限時間を枚数で等分して順に切り替わる。枚数は選択肢ごとに違ってもよい。

```
https://example.com/1.jpg|https://example.com/2.jpg
```

URLはブラウザが直接読み込める画像のものにする。Googleドライブの共有リンク（`drive.google.com/file/d/.../view`）はHTMLページのURLなので表示されない。パブリックアクセスのストレージに置き、HTTPSで指定する。

## 当日の進行

1. 参加者用URLをQRコードやチャットで配布する
2. 参加者は名前を入力して参加する
3. 管理画面で問題の「出題」を押す。8秒のカウントダウンののち、全端末で一斉に問題が表示される
4. 制限時間が過ぎると、参加者の画面に選択肢ごとの回答数が表示される
5. 「正解発表」を押す
6. 次の問題の「出題」を押す

問題と問題の間を空けたいときは「待機に戻す」を押すと、参加者画面が準備中の表示になる。データは消えない。

### やり直すとき

回答シートの2行目以降を削除する。管理画面の回答数が問題IDで集計しているため、古い行が残っていると件数が合わなくなる。

参加者側は出題し直すと自動でリセットされるので、操作は不要。問題シートの最終出題時刻は記録用なので消さなくてよい。

## 集計

回答シートに全問題の回答が集まる。

| 列 | 項目 | 内容 |
|---|---|---|
| A | 記録時刻 | サーバーが記録した時刻 |
| B | 問題ID | |
| C | 名前 | |
| D | 回答 | 1〜4 |
| E | 回答タイムms | 問題が表示されてから回答するまでの時間。**順位にはこれを使う** |
| F | 正誤 | 1 / 0 |
| G | 時間外 | 1 / 0 |
| H | サーバー計測ms(参考) | サーバーが受信するまでの時間。通信の遅延を含むため順位には使わない |

### 問題別結果シート

各問題の早押し順位は問題別結果シートで見る。B1の問題IDをプルダウンから選ぶと、その問題の正解者が回答タイムの速い順に並ぶ。時間外の回答は除外される。

集計はすべてシートの関数で行っているため、回答シートの行が増えれば自動で反映される。関数を消してしまった場合は `setupSheets` を実行し直せば元に戻る。

### 最終結果シート

全問を通した順位は最終結果シートで見る。正解数の多い順に並び、正解数が同じ場合は正解した問題の合計タイムが短い方が上位になる。

名前は参加者シートから取るため、1問も答えなかった人も0正解として最下位に並ぶ。時間外の回答は正解数とタイムのどちらからも除外している。

G列より右は集計の途中結果を置く作業用の列で、見た目が気になる場合は非表示にしてよい。

ランキングを表示する画面はないため、集計はスプレッドシート側で行う。

## 割り切っている仕様

余興用のため、次のケースは考慮していない。

- 参加者は名前で一意に扱う。重複した名前は区別できない
- 再入場時の名前変更はできない
- 回答は変更できない。二重送信の防止はブラウザ側のみで行っている
- 途中から参加した人の未回答の問題は不正解として扱う
- 正解数と合計タイムが完全に一致した場合の順位は保証しない
- 未回答者がいても進行できる。全員の回答は待たない
- 経過時間はクライアントが申告した値のため、詐称の余地がある
- 管理画面にアクセス制限がない。URLに `?page=admin` を付けるだけで開けるため、URLの扱いに注意する
